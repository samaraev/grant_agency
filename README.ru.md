# ГРАНТ — Дом изнутри (агентство Grant)

Гиперлокальный сайт агентства недвижимости **и** бэк-офис для **Хамовников**. Публичная часть — база домов «от адреса» с редакционными страницами для собственников и покупателей. Приватная часть — полноценная внутренняя CRM: десятиэтапная воронка обращений, коммуникации, сценарии сообщений, встречи, задачи, документы, отчёты и Яндекс.Метрика в двуязычном интерфейсе (RU/EN).

- Опубликованное приложение: <https://grant-home-inside.base44.app>
- English version of this document: [README.md](README.md)

> Публичный интерфейс по умолчанию русский; английский включается переключателем RU/EN в шапке сайта и в админ-панели. **Контент для клиента** (приветствие в WhatsApp, темы писем, пример строки в CSV-шаблоне, служебные заметки в базе) остаётся русским осознанно — это данные, а не интерфейс.

## 2. Принципы продукта

Это правила продукта, а не вкусовые предпочтения. Их изменение — продуктовое решение.

1. **Никаких автоматических оценок.** Цена никогда не считается из квадратных метров. Цена появляется только как ручная заметка эксперта (`OwnerAnalysis.price_range_note`).
2. **Никаких обещаний результата.** Интерфейс не обещает срок продажи, число показов, скидку, «лучшее агентство» или «самую низкую комиссию».
3. **Собственник впереди.** Сценарии собственника идут раньше покупательских и в навигации, и на главной; покупательская воронка существует, чтобы обслуживать продажу собственника.
4. **Один район осознанно.** Хамовники (`cluster: "khamovniki"`) — целевой кластер; всё остальное — `other`, а `area_flag` это фиксирует.
5. **Осмотрительность.** Адрес, фотографии и цена объектов приватного портфеля публикуются только с согласия собственника; данные клиентов не передаются третьим лицам (`Lead`, `Document`).
6. **Непредставленные услуги помечены «Планируем» (`planned`)** и никогда не подаются как действующие. Это задаёт поле `Service.status`.
7. **Спокойный премиальный тон.** Без риелторских клише, восклицательных знаков и превосходных степеней; вместо этого — конкретные факты о конкретном доме.
8. **Данные важнее декора.** Каждое число, которое видит администратор, приходит из базы или из Метрики; выводы пишет человек.

### 4.3 Поиск по адресу

`components/AddressSearch.jsx` сверяет введённое с уже загруженными домами (адрес, улица, район, город).

- **Совпадение** → переход на `/house/:id`.
- **Нет совпадения** → переход на `/search?q=…`, где пустой результат предлагает оставить адрес обращением.
- Оба исхода отправляют `address_search` с `matched: true|false`.

### 4.4 Страница поиска

Фильтры хранятся в адресе, поэтому любой вид можно передать ссылкой:

| Параметр | Значение |
| --- | --- |
| `q` | Полный текст по адресу, улице, району, городу |
| `district` | Фильтр по району |
| `street` | Фильтр по улице |
| `group` | `offices` \| `residences` \| `estates` (сопоставление `property_type` через `PROPERTY_GROUPS`) |
| `deal` | `sale` \| `rent` |

Виды: **список** (карточки) и **карта**. `PROPERTY_GROUPS` в `lib/price.js`: `offices → office, corporate_housing`; `residences → apartment, penthouse`; `estates → dacha, estate`. Тип `residential` доступен без фильтра по группе.

### 4.5 Страница дома

Порядок блоков: факты (год, этажность, подъезды, квартиры, серия, площадь, цена, тип сделки, потолки, лифт, метро), редакционное описание, особенности (`Building.features[]`), заметки по квартирам (`ApartmentNote`: тип планировки, диапазон площади, типичные вопросы, ликвидность), галерея, видео, карта Leaflet и три кнопки-решения, которые открывают форму обращения **с подставленным адресом** и нужным типом (`owner_appraise`, `owner_sell`, `buyer_buy`).

Формат цены (`lib/price.js`): `1 200 000 ₽`, для `deal_type: "rent"` добавляется «в месяц»; пустая цена выводится как «Цена по запросу».

### 4.6 Содержательные страницы

- **Собственникам** — шесть вопросов, с которыми приходят, «как проходит консультация» (заявка → подготовка → разговор → решение), «чего мы не делаем» (автоматическая оценка, обещанные сроки, публикация без согласия), форма и ссылка на страницу кластера.
- **Покупателям** — шесть вопросов покупателя и чек-лист из восьми пунктов (право собственности и обременения, цепочка владельцев, состояние конструкции, коммуникации, оригинальные детали, согласования и перепланировки, соседи и управление, планы вокруг дома).
- **Хамовники (кластер)** — первый экран, четыре причины работать одним кластером, процесс из четырёх шагов (заявка → квалифицированный разговор → договор → сделка), четыре заявленных ограничения, блок контакта с ответственным и часами, поиск и форма.
- **Услуги** — записи `Service`, разделённые по `status` на «действует сейчас» и «планируется» (метка видна), плюс дорожная карта из четырёх этапов (сайт → первые обращения → контент → дальнейшие услуги).
- **О нас** — позиционирование, история из четырёх абзацев, три опоры, карточки `TeamMember` (только `is_public: true`) и `Claim` с `is_verified: true` и пометкой о доказательстве.
- **Контакты** — адрес офиса, ориентир, часы, карта, форма обращения.
- **Политика конфиденциальности** — восемь разделов (какие данные, зачем, правовые основания, передача, хранение, права, запись звонков, каналы связи) с явной пометкой, что нужны реквизиты компании и юридическая проверка.

## 5. Приём обращений

Одна форма (`components/LeadForm.jsx`) в одном диалоге (`components/LeadDialog.jsx`), открывается откуда угодно через `LeadProvider` / `useLead()`: кнопка в шапке, кнопки первого экрана, страница дома, страница кластера, пустой результат поиска, страницы собственникам / покупателям / контактам и подсказки в админке.

### 5.1 Поля

| Поле | Тип | Заметки |
| --- | --- | --- |
| `type` | enum | `owner_appraise`, `owner_sell`, `buyer_buy`, `buyer_check`, `general`, `rent` |
| `address_text` | текст | Подсказки из загруженных домов, свободный ввод разрешён |
| `name` | текст | ≥ 2 символов, обязательно |
| `phone` | текст | Приводится к 11 цифрам, обязательно |
| `preferred_contact` | enum | в публичной форме `phone` (по умолчанию), `telegram`, `whatsapp`; в сущности есть также `max` и `email` |
| `sell_timeline` | enum | `asap`, `month`, `quarter`, `later`, `undecided` (сценарии собственника) |
| `message` | textarea | Необязательный комментарий |
| согласие | boolean | Обязательно; сохраняются `consent_at` и `consent_text_version` |
| ловушка | скрытое поле | Любое значение → тихий успех, ничего не пишется |

### 5.2 Серверный контракт (`functions/submitLead`)

1. **Валидация** — имя ≥ 2 символов, 11-значный телефон, `consent === true`; иначе 400 с ошибкой по полю.
2. **Ловушка** — заполнена → `{ ok: true }` без записи. Бот ничего не узнаёт.
3. **Ограничение частоты** — по IP в окне 10 минут; при превышении `429 { error: "rate_limited" }`. Интерфейс показывает «слишком много запросов, позвоните нам».
4. **Сопоставление дома** — введённый адрес сверяется с `Building` и сохраняется в `building_id`, если найден.
5. **Вывод полей** — `pipeline` (`owner_sale` / `buyer_search` / `rental`), `cluster` (`khamovniki` / `other`) и `person_role` (`owner` / `buyer` / `tenant` / `other`) выводятся из типа обращения и адреса; `area_flag` фиксирует `in_target` / `outside` / `unknown`.
6. **Атрибуция** — UTM-параметры (хранятся в `sessionStorage` до конца сессии), иначе `referrer`, иначе `direct`; `utm_*`, `referrer`, `page_path` и **ClientID** Метрики сохраняются в обращении (`client_id`).
7. **Создание** — `status: "new_inquiry"`, `consent_at` и первая запись в `StatusHistory`.
8. **Уведомление** — письмо на `AdminSettings.default_responsible`, иначе на `SiteSettings.admin_email`.

После отправки посетитель видит подтверждение с блоком «что дальше» (архивы → связь → встреча).

## 6. Админ-панель

Маршруты в `src/pages/admin/*`; оболочка, навигация и переключатель языка — в `AdminLayout.jsx`. Меню сгруппировано по рабочему сценарию:

- **Каждый день** — Дашборд, Сегодня, Задачи, Обращения, Воронка
- **Клиенты** — Встречи, Сценарии, Отчёты
- **Каталог** — Дома, Услуги, Команда
- **Система** — Аналитика, Метрика, Интеграции, Запуск проекта, Настройки

Внизу — «На сайт», выход и почта вошедшего; на телефоне то же меню открывается кнопкой в шапке.

### 6.1 Дашборд — `/admin`

Загружает до 300 обращений, первую запись `AdminSettings` и до 200 открытых задач, затем показывает четыре уровня приоритета:

1. **Центр действий** (`components/admin/dashboard/ActionCenter.jsx`) — просроченные первые ответы (SLA), задачи на сегодня и просроченные (до трёх ближайших с переключателем «Выполнено», который зачёркивает задачу), новые обращения без ответа.
2. **Здоровье воронки** (`FunnelHealth.jsx`) — десять этапов, сгруппированные в «в работе» и «результат», доля Хамовников, собственники и покупатели, квалифицированные разговоры.
3. **Распределение** (`DistributionCard.jsx` + `BarRow.jsx`) — две карточки: обращения по типу и по источнику (UTM), топ-5, остальное свёрнуто в «другие».
4. **Последние обращения** (`RecentLeads.jsx`) — пять последних с типом, статусом и датой; на телефоне тип уходит на отдельную строку.

### 6.3 Загрузки в админке

- Фото домов и команды используют `UploadPublicFile` — **хранятся публично (любой со ссылкой может открыть)**, потому что показываются на публичном сайте.
- Документы клиентов используют `UploadPrivateFile` — **хранятся приватно**, открываются только по короткоживущей подписанной ссылке из `getDocumentUrl`.

### 6.4 CSV по домам

Выгрузка содержит все дома, `features` склеиваются через `; `. Импорт сопоставляет строки по `address` (без учёта регистра): существующие адреса обновляются, новые создаются, диалог показывает количество созданных / обновлённых / ошибочных.

Колонки импорта: `address`, `property_type`, `deal_type`, `price`, `area`, `district`, `street`, `house_number`, `year_built`, `series_or_type`, `floors`, `entrances`, `apartments_count`, `description`, `features`, `latitude`, `longitude`, `is_priority`, `expert_verified`, `verified_at`, `verified_by`; `is_published` учитывается, если указан (`"false"` оставляет строку черновиком). Массивы фото и видео импортом не перезаписываются.

## 7. Воронка обращений

Десять статусов, зеркально на клиенте (`src/lib/leadStatus.js`) и на сервере (`base44/shared/leadFunnel.ts`):

| № | Статус | Подпись | Смысл |
| --- | --- | --- | --- |
| 1 | `new_inquiry` | Новое обращение | Только пришло, никто ещё не ответил |
| 2 | `contact_made` | Контакт установлен | Зафиксирован первый исходящий контакт |
| 3 | `target_inquiry` | Целевое обращение | Объект и человек соответствуют целевому кластеру |
| 4 | `qualified_conversation` | Квалифицированный разговор | Состоялся разговор по сути — **это KPI** |
| 5 | `meeting_scheduled` | Встреча назначена | Встреча согласована и стоит в календаре |
| 6 | `meeting_held` | Встреча проведена | Встреча состоялась |
| 7 | `contract_signed` | Договор подписан | Подписан агентский или эксклюзивный договор |
| 8 | `listed_or_search_started` | В продаже / подбор начат | Объект выставлен или подбор покупателя начат |
| 9 | `deal_closed` | Сделка | Сделка закрыта |
| 10 | `non_target` | Нецелевое обращение | Отказ, требуется причина |

Правила, которые проверяет `functions/changeLeadStatus` (и зеркально клиент — `needsTransitionData`):

- **Канбан** показывает первые девять статусов как колонки; у `non_target` своя колонка, туда ведёт диалог перехода.
- `qualified_conversation` требует чек-лист: `owner_need_confirmed`, `object_confirmed`, `real_intent`, `timeframe_recorded`, `meeting_agreed`, `terms_fit`.
- `target_inquiry` для обращения с `area_flag: "outside"` тоже требует чек-лист (исключение по кластеру).
- `contract_signed` требует `contract_type` (`agency` / `exclusive`) и `contract_url`.
- `non_target` требует `rejection_reason` (справочник в сущности `RejectionReason`).
- Каждая смена проставляет `first_response_at` (первый исходящий контакт) и `qualified_at`, пишет запись в `StatusHistory` с автором, а затем запускает офлайн-конверсию в Метрику и сценарий по статусу. **Сбой интеграции никогда не блокирует смену статуса.**
- Устаревшие статусы (`new`, `contacted`, `qualified`, `meeting_set`, `agreement`, `closed`, `spam`) приводятся при чтении (`LEGACY_STATUS_MAP`); `migrateLeadStatuses` переписывает их в базе (по умолчанию пробный прогон).
- Фильтрация по статусу идёт через `statusQuery()`, поэтому старые записи тоже попадают в выборку нового статуса.

В карточке обращения есть **чек-лист пути** (`lib/leadJourney.js`), шаги которого зависят от `person_role`: собственник, покупатель или общий путь из пяти шагов. `journeyProgress` считает пройденные шаги.

**Экономика сделки** (`lib/deal.js`): `deal_value` + `deal_currency` (`RUB`, `USD`, `EUR`), `commission_percent`, вычисляемая `commission_amount`, `commission_note` для условий текстом, `expected_close_date`, `closed_at`.

## 8. Норматив первого ответа

`src/lib/sla.js` считает **только рабочее время**: понедельник–пятница внутри окна из `AdminSettings` (`working_hours_start` 10:00, `working_hours_end` 20:00), всегда по московскому времени (`MSK_OFFSET_MIN = 180`).

- Норматив: `first_response_sla_minutes`, по умолчанию **30**.
- Закрытые статусы (`non_target`, `deal_closed`) никогда не считаются просроченными.
- Обращение без `first_response_at`, у которого отработанных минут больше норматива, считается **просроченным**; `slaState()` возвращает состояние, отработанные минуты и остаток/переработку.
- Число видно в трёх местах: «Центр действий» на `/admin`, список `/admin/today` (с отработанным временем) и утренний дайджест.

## 9. Задачи

Записи `Task`: `title`, `due_at` (дата и время), `assignee` (почта администратора), `priority` (`low` / `normal` / `high`), `status` (`open` / `done` / `cancelled`), необязательный `lead_id`, `notes`, `created_by`, `reminder_sent`.

- Управление на `/admin/tasks` (`TasksTable` + `TaskDialog`), из обзора обращения (`LeadTasksCard`), из `/admin/today` (`TasksPanel`) и из «Центра действий» на дашборде.
- `lib/tasks.js` содержит перечисления, карты тонов, `isOverdue`, `isDueToday`, `dueLabel`, `leadLabel` и `sortTasks`.
- Workflow **TaskReminders** (ежедневно 09:30 МСК) вызывает `sendTaskReminders`: открытые задачи на сегодня и просроченные группируются по ответственному, каждый получает одно письмо, `reminder_sent` защищает от повторов. Ту же рассылку можно запустить вручную из `/admin/tasks`.

## 10. Коммуникации

У каждого обращения есть лента записей `Communication`: `channel` (`email`, `sms`, `call`, `telegram`, `whatsapp`, `max`, `note`), `direction` (`in` / `out`), `subject`, `body`, `status` (`queued`, `sent`, `delivered`, `failed`, `answered`, `missed`), `provider_id`, `duration_seconds`, `recording_url`, `created_by`, `scheduled_at`, `sent_at`, `sequence_key`.

| Канал | Механика |
| --- | --- |
| **Почта** | `sendEmail` подставляет поля в `MessageTemplate` (`{имя}`, `{адрес}`, `{ответственный}`, `{телефон}`, `{время_встречи}`), отправляет письмо и пишет `Communication`. Встроенная отправка, ключи не нужны. До подключения собственного домена письма доходят только зарегистрированным пользователям приложения. |
| **SMS** | `sendSms` использует провайдера, выбранного на `/admin/integrations`: sms.ru, SMSC.ru или Twilio. Маркетинговые тексты требуют согласия клиента. |
| **Звонки** | `startCall` — звонок в два шага: сначала провайдер звонит администратору, затем клиенту. Поддерживаются Zadarma, Novofon, Telphin, Mango Office. |
| **Статусы доставки** | `commsWebhook` принимает колбэки провайдера (доставлено / отвечено / пропущено / ошибка …) и обновляет запись; защищён секретным токеном, доступен по `/functions/commsWebhook?token=…`. |
| **Ручная фиксация** | Звонок, сообщение или заметку всегда можно записать руками (`CommsLogDialog`, `CommsQuickActions`), если провайдер не подключён. WhatsApp работает как ссылка плюс ручная запись. |
| **Подсказка сценария** | Карточка обращения предлагает готовый текст под текущий статус и отправляет его в один клик по каналу (`SequenceSuggestPanel`). |

## 11. Сценарии сообщений

`SequenceSetting` — одна запись на сценарий **и** канал (`email`, `sms`, `whatsapp`) с `template_key`, `auto_send`, `delay_hours`, `is_active`. Логика — в `base44/shared/sequences.ts`.

| Сценарий | Триггер |
| --- | --- |
| `first_reply` | статус `new_inquiry` |
| `meeting_confirmation` | статус `meeting_scheduled` |
| `thank_you_after_meeting` | статус `meeting_held` |
| `no_answer` | статус `contact_made` без отвеченного исходящего звонка за последние 24 часа |
| `price_analysis_followup` | статус `qualified_conversation`, когда анализ для собственника заполнен |

Правила:

- `first_reply` и `meeting_confirmation` — **транзакционные** (`TRANSACTIONAL_KEYS`) и согласия не требуют; остальные три требуют `consent_at`.
- Вне рабочих часов (10:00–20:00 МСК) автоотправка ставится в очередь до следующего рабочего утра.
- Задержка больше нуля тоже ставит сообщение в очередь; `dispatchSequences` (каждые 15 минут) отправляет всё созревшее и помечает ошибки, не повторяя их бесконечно.
- У WhatsApp здесь нет API: сообщение готовится как ссылка и отмечается отправленным вручную.
- Дважды ничего не отправляется: строки с `sent_at` пропускаются.

## 12. Встречи

Записи `Meeting`: `type` (`in_apartment`, `office`, `video`), `starts_at`, `address`, `responsible`, `status` (`planned`, `held`, `cancelled`, `no_show`), `result_notes`.

- Создаются из карточки обращения (`LeadMeetingsTab`) или с `/admin/meetings`; календарь и список — одни и те же данные в двух видах (`MeetingsCalendar`).
- Назначение встречи переводит обращение в `meeting_scheduled`; отметка «проведена» — в `meeting_held`.
- При назначении можно отправить подтверждение клиенту; можно назначить и без подтверждения.
- Экспорт `.ics` по встрече (`lib/ics.js`) работает с обоих экранов.
- Встречи питают дашборд, `/admin/today` и дайджест.

## 13. Документы

Записи `Document` привязаны к обращению: `doc_type` (`contract`, `passport`, `extract`, `valuation`, `other`), `title`, `file_ref` (приватный `file_uri`), `external_link`, `file_size`, `uploaded_by`, `notes`.

- Файлы загружаются через `UploadPrivateFile` — **хранятся приватно**: публичной ссылки нет, браузер никогда не получает постоянный адрес.
- `getDocumentUrl` выдаёт короткоживущую подписанную ссылку и пишет `document.url_issued` в журнал действий; `deleteDocument` пишет `document.deleted`.
- Вкладка «Документы» (`LeadDocumentsTab`, `DocumentUploadDialog`) показывает название, тип, автора, дату и размер, умеет открыть, скачать и удалить. Вместо файла можно сохранить внешнюю ссылку.
- В интерфейсе есть явное предупреждение: документы содержат персональные данные, доступ пишется в журнал, сканы паспорта загружаются только когда это требуют регламенты.

## 14. Отчёты и дайджест

- `/admin/reports` собирает недельный или месячный `Report`: `period_start` / `period_end`, `metrics` (JSON-строка, посчитанная по CRM) и шесть текстовых блоков, которые пишутся руками — `done_text`, `implemented_text`, `checked_text`, `data_text`, `blocked_text`, `next_text`. Отчёт можно сохранить, распечатать в PDF (печать целится в `#report-print` через `@media print`) и отправить письмом (`sendDigest` с `mode: "report"`).
- Workflow **DailyDigest** запускается ежедневно в **09:30 Europe/Moscow** и вызывает `sendDigest` с `mode: "digest"`: новые обращения, просроченные первые ответы, сегодняшние встречи и ближайшие действия со ссылками внутрь приложения.
- Получатели: `AdminSettings.admin_email`, `default_responsible`, `backup_responsible` и администраторы приложения — без повторов.
- Тот же дайджест можно отправить вручную со страницы `/admin/reports`.

## 15. Яндекс.Метрика

Настройки — в `IntegrationSettings` (одна запись), правятся на `/admin/integrations`; OAuth-токен лежит только в секретах как `METRICA_OAUTH_TOKEN`.

- **Клиентская часть** — при включённом `metrica_enabled` `Layout` / `hooks/useThirdPartyTags.js` вставляют счётчик; `lib/track.js` отправляет события интерфейса и клиентские цели (`lead_submit`, `phone_click`, `form_start`) через `ym('reachGoal')`. ID целей берутся из `metrica_goal_ids` (ключи: `lead_submit`, `phone_click`, `form_start`, `qualified_conversation`, `contract_signed`, `deal_closed`). ClientID сохраняется в обращении (`client_id`) — именно он делает возможными офлайн-конверсии.
- **Офлайн-конверсии** — `uploadOfflineConversion` отправляет `qualified_conversation`, `contract_signed` и `deal_closed` по ClientID (для закрытой сделки — с суммой). Запускается автоматически из `changeLeadStatus` и вручную из обзора обращения (`MetricaConversionCard`). `Lead.offline_conversions_sent[]` защищает от повторов, попытка пишется в журнал (`metrica.offline_conversion`, `metrica.offline_conversion_failed`).
- **Отчётность** — `fetchMetricaStats` читает Reporting API Метрики и кэширует ответы на **10 минут** для `/admin/metrica`; `metricaConfig` проверяет счётчик, сохраняет настройки и сообщает, есть ли токен.
- Без токена счётчик, цели и захват ClientID работают; недоступны только отчётность и офлайн-конверсии.

## 16. Журнал действий

`AuditLog` фиксирует `actor` (почта администратора или `demo`), `action`, `entity`, `entity_id`, `meta`, `at`. Показывается только для чтения на `/admin/settings` (`AuditLogPanel`, последние 100 записей) и закрыт на уровне сущности для всех, кроме администратора.

Пишутся действия: `document.url_issued`, `document.deleted`, `lead.exported`, `metrica.offline_conversion`, `metrica.offline_conversion_failed`.

## 21. Двуязычный интерфейс

- Словари: `src/content/ru.js` и `src/content/en.js` — один файл на язык, **одинаковые наборы ключей** (по 1 272 ключа); тексты главной в `src/content/homepage.js` экспортируются на язык и подмешиваются в `t.homepage`.
- `src/lib/i18n.js` отдаёт живой объект `t`, `applyLanguage(code)`, `dateLocale()` (`ru-RU` / `en-GB`) и `LANGS`.
- `components/LanguageProvider.jsx` хранит выбор в `localStorage` (`grant_lang`), по умолчанию русский, и перемонтирует поддерево (`key={lang}`) при переключении — поэтому ни один экран не может сохранить устаревшие строки или устаревшие мемоизированные подписи.
- `LanguageSwitcher` стоит в шапке сайта и в админ-панели.
- Строки интерфейса берутся только из `t.*`. Данные из базы (описание дома, название шаблона) показываются как сохранены.
- **Что остаётся русским осознанно:** тексты сообщений клиенту, темы писем для клиента, пример строки в CSV-шаблоне и служебные заметки в записях. Это контент, а не интерфейс.
- **Новый язык:** создать `src/content/<code>.js` с тем же набором ключей и добавить одну запись в `LANGS`.
- **Новая строка:** добавить ключ в оба словаря в одном коммите; отсутствующий английский ключ даёт пустую подпись, а не откат на русский, поэтому файлы нужно держать синхронными.

## 22. SEO

- `src/lib/seo.js` задаёт title, description, robots, canonical, Open Graph, локаль и JSON-LD для каждой страницы. `organizationJsonLd(settings)` собирает разметку агентства `RealEstateAgent` + `LocalBusiness`; страница дома передаёт в `applySeo` собственную разметку дома, а `applySeo` убирает все вставленные скрипты при размонтировании.

- Имена классов Tailwind должны быть литеральными строками — никакой сборки вида `bg-${color}-500`.
- Всё адаптивно; дашборды и админ-меню проверяются на телефоне и десктопе.
- Контентные изображения рендерятся через `components/ui/image.jsx` (адаптивный srcset), а не обычным `<img>`.

## 26. Авторизация и доступ

- Вход по почте и паролю (`loginWithMfa`, включая шаг MFA, если он включён), вход через Google, восстановление пароля (`/forgot-password`, `/reset-password?token=…`) и двухфакторная аутентификация (`/mfa`, `MfaFlow`, `MfaManage`, `MfaMethodSetup`).
- Новые пользователи приходят через страницу **App Users**; роли — `admin` и `user`.
- **Задуманная модель:** `/admin` открывается только для `role = "admin"`; чтение обращений ограничено автором или администратором; запись в каталог, настройки и CRM — только администратору.
- **Текущее состояние (демо):** проверка входа в админку отключена (`GATE_DISABLED = true` в `AdminLayout.jsx`), маршруты `/admin` в `App.jsx` не обёрнуты в `ProtectedRoute`, `requireAdminOrDemo` пропускает запросы без сессии, а блоки `rls` сущностей открыты. Это только для показа — приложение ведёт себя так, будто каждый посетитель администратор.

**Чтобы вернуть продакшн-доступ:**

1. Поставьте `GATE_DISABLED = false` в `src/pages/admin/AdminLayout.jsx` и оберните маршруты `/admin` в `src/App.jsx` компонентом `<Route element={<ProtectedRoute unauthenticatedElement={<Navigate to="/login" replace />} />}>`.
2. Замените демо-тело `requireAdminOrDemo` в `base44/shared/guards.ts` строгой проверкой `user.role === "admin"` с ответом 403 — её вызывают все админские функции.
3. Ужесточите `rls` сущностей: публичное чтение `Building`, `Service`, `SiteSettings`, `ApartmentNote` и опубликованных `TeamMember`; только создание — `Events` и `Lead`; только администратор — обращения, коммуникации, документы, задачи, встречи, отчёты, сценарии, воронки и настройки.
4. После изменения перепроверьте `/admin/today` и дашборд: администратор должен их видеть, все остальные — экран отказа в доступе.

3. `npm install -g base44@latest` (Base44 CLI).
4. Установить [Deno](https://docs.deno.com/runtime/getting_started/installation/) — локальный бэкенд Base44 работает на нём.

`base44 --help` показывает полный набор команд ([справочник CLI](https://docs.base44.com/developers/references/cli/commands/introduction)).

### Запуск

```bash
base44 login   # один раз на машину
base44 link    # один раз на клон
base44 dev     # локальный бэкенд + фронтенд вместе
```

Откройте адрес фронтенда, который напечатает `base44 dev` (обычно `http://localhost:5173`).

Заметки:

- **Каждому новому клону нужен `base44 link`** — он пишет `base44/.app.jsonc`, указатель на приложение, который намеренно в gitignore.
- **`base44 dev` сам запускает фронтенд** (через `site.serveCommand`), не запускайте `npm run dev` отдельно.
- **Приложение должно быть хотя бы раз опубликовано**, иначе UI не загрузится под `base44 dev`.
- Сущности, функции и авторизация работают локально; данные сущностей **только в памяти** и стираются при перезапуске. Core-интеграции и OAuth-вход проксируются на развёрнутое приложение.

### Только фронтенд, бэкенд в облаке

```bash
base44 dev --remote
```

⚠️ В этом режиме запись идёт в **боевые данные** приложения.

### Публикация

После пуша в git публикуйте из панели (`base44 dashboard open`). Синхронизация идёт через git; деплой из CLI отправил бы локальное дерево напрямую.

```bash
npm run build       # продакшн-сборка
```

## 28. Регламент эксплуатации

**Добавить дом**
`/admin/buildings` → «Добавить дом» → адрес (уникальный), город, район, тип сделки, цена, площадь, год, этажность, подъезды, серия, описание, особенности, координаты, фото → флаг публикации. Приоритет и «проверено экспертом» поднимают дом в списках и в подборке главной.

**Заполнить базу пакетно**
`/admin/buildings` → «Импорт CSV». Файл сопоставляется по адресу: существующие строки обновляются, новые создаются, диалог показывает созданные / обновлённые / ошибочные. Шаблон скачивается оттуда же.

**Поменять палитру или шрифты**
Правьте значения токенов в `src/index.css` (`:root` и `.dark`), остальное подтянется через `tailwind.config.js`. Не добавляйте hex в компоненты.

**Изменить рабочие часы или норматив SLA**
`AdminSettings.working_hours_start`, `working_hours_end`, `first_response_sla_minutes`, `timezone`. SLA, «Сегодня», дашборд и дайджест читают одну и ту же запись.

**Изменить получателей уведомлений**
`AdminSettings.default_responsible` (основной) и `backup_responsible` (резервный), плюс `SiteSettings.admin_email`. Дайджест также уходит всем администраторам приложения.

**Включить SMS или звонки**
`/admin/integrations`: выбрать провайдера, задать имя отправителя и номер администратора, добавить ключи провайдера в секреты, нажать «Отправить тест». Передать провайдеру адрес вебхука с `?token=`, совпадающим с `COMMS_WEBHOOK_TOKEN`.

**Включить отчётность Метрики**
Добавить `METRICA_OAUTH_TOKEN` в секреты, указать номер счётчика и ID целей на `/admin/integrations`, включить счётчик, нажать «Проверить подключение».

**Добавить или переписать автосообщение**
Текст хранится в `MessageTemplate`; `SequenceSetting` связывает шаблон со сценарием и каналом (`auto_send`, `delay_hours`, `is_active`). Проверьте через «Подсказку сценария» в карточке обращения, прежде чем включать автоотправку.

**Изменить правила воронки**
`base44/shared/leadFunnel.ts` (сервер) и `src/lib/leadStatus.js` (клиент) должны совпадать — чек-листы, обязательные данные и карта старых статусов живут в обоих файлах.

**Разобраться с упавшей автоматизацией**
Дашборд → Workflows → прогоны нужного workflow (шаги, ошибки, версия определения); логи конкретной функции; `/admin/settings` — журнал чувствительных действий.

**Сменить токен вебхука**
Сгенерировать новое значение в секретах как `COMMS_WEBHOOK_TOKEN` и обновить адрес в панели провайдера.

## 29. Известные ограничения

- **Демо-доступ**: проверка админки, защита маршрутов и RLS сущностей открыты (см. [раздел 26](#26-авторизация-и-доступ)).
- **Домен**: canonical, sitemap, robots и метаданные `index.html` всё ещё используют `https://rieltorcenter.ru`.
- **Контакты** в `SiteSettings` — заглушки: телефон, почта и офис требуют подтверждения до запуска.
- **Политика конфиденциальности** — структурированный черновик: нужны реквизиты компании и юридическая проверка.
- **SMS, телефония и мессенджеры**: адаптеры реализованы, для боевой отправки нужны ключи провайдеров и токен вебхука. WhatsApp работает как ссылка плюс ручная отметка — API-интеграции нет.
- **Метрика**: отчётность и офлайн-конверсии требуют `METRICA_OAUTH_TOKEN`; счётчик, цели и захват ClientID работают и без него.
- **Письма на незарегистрированные адреса** требуют подключённого собственного домена на платном плане; до этого почту получают только зарегистрированные пользователи приложения.
- **Оплат и онлайн-записи нет**: сайт работает через обращения и встречи.
- **Автоматических оценок нет** по замыслу; анализ для собственника пишется руками в карточке обращения.
- **Отправка отчёта письмом** подчиняется тому же ограничению по получателям.
- **Пагинация**: админ-экраны загружают одну страницу записей (300–800 в зависимости от экрана); выше этих объёмов спискам и счётчикам нужны серверные агрегаты.
- **Медиа** хранятся ссылками; фото домов и команды загружаются из админки, документы клиентов идут в приватное хранилище.

- Серверная пагинация и агрегаты для журнала обращений и аналитики.

## 30. Глоссарий

| Термин | Значение |
| --- | --- |
| **Дом** | Конкретный адрес со своими фактами, особенностями и историей — единица всего продукта |
| **Кластер** | Рабочий район; первый и пока единственный — Хамовники |
| **Обращение (lead)** | Один входящий запрос; единственное, что фиксирует CRM на входе |
| **Квалифицированный разговор** | Разговор по сути; KPI агентства, а не отправленная форма |
| **Нецелевое обращение** | Отказ агентства, всегда с зафиксированной причиной |
| **Воронка (pipeline)** | Путь обращения: `owner_sale`, `buyer_search`, `rental` |
| **Анализ для собственника** | Ручная заметка эксперта о цене, ликвидности, конкурентах, рисках и стратегии — никогда не автоматическая оценка |
| **Сценарий** | Набор сообщений по статусу для конкретного канала |
| **Портфель** | Набор опубликованных домов; приватные объекты показываются только по запросу |
| **Агентский / эксклюзивный договор** | Два типа договора в поле `contract_type` |
| **Дайджест** | Ежедневное письмо-сводка команде в 09:30 |
